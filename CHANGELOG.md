# Changelog

Notable changes to Stanchion are recorded here. The project follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and intends to use
[Semantic Versioning](https://semver.org/) after the first stable release.

## [Unreleased]

### Security
- A sender **allow** rule now applies only when the message passed DMARC at the trusted boundary; otherwise the spam score still decides (a **block** rule always applies). The trace notes "allow rule ignored" when it happens.
- A message carrying a second `Authentication-Results` record that claims the boundary's own id is treated as forged: no SPF, DKIM or DMARC verdict from it is trusted.
- A read-only delegate can no longer send a calendar reply (RSVP) as the mailbox, and no longer sees the RSVP buttons.

### Changed
- Mail whose HTML is too large or too deep to display is no longer bounced: it is delivered showing its plain-text part (or a short notice), with the original message attached as `original-message.eml` when it fits the attachment limit.

## [0.9.0-beta.3] - 2026-11-23

**Highlights**

- The product is now called Stanchion (formerly cMail). Repo: RME-Solutions-Technology/stanchion; old links redirect.
- Passkeys: Add a phone with a QR code (migration 0034, additive).
- A busy hour no longer bounces real mail: rate limits now hold mail in Junk instead of a permanent rejection.
- One Microsoft 365 admin page.

Migrations: 0034 (additive). Details below.

### Security
- Inbound rate limits (messages or bytes per hour, messages per sender) no longer end in a permanent SMTP rejection. A tripped limit files the message to Junk with the reason "held: too much mail arrived at once"; a known correspondent (someone you wrote to, or whose mail you read) with a DMARC pass keeps the Inbox. A missing or malformed `INBOUND_SENDER_HASH_KEY` now skips only the per-sender limit (logged) instead of rejecting all mail. Only the storage quota still rejects. No migration.

### Added
- Passkeys: **Add a phone** on Mail > Settings > Passkeys. Show a QR code, scan it with the phone camera, approve the phone on the page you are signed in on, and the phone creates its own passkey for your account (no sign-in or typing on the phone). One-time 10 minute offer, token in the URL fragment and stored only as a hash, approval by matching a two-digit number shown on the phone (three wrong picks cancel it), the offer needs a session under 5 minutes old, one open offer per person, the registration challenge bound to the offer, every step audited and rate limited, QR drawn as inline SVG with the MIT `qrcode-generator` 2.0.4 (pinned). Needs migration `0034` (one new table, additive). Details: docs/passkeys.md.

### Changed
- Product renamed from cMail to Stanchion (formerly cMail). The GitHub repo is now `RME-Solutions-Technology/stanchion` (old links redirect) and the developer package scope is `@stanchion/*`. Names live systems depend on (cookies `cmail_*`, `CMAIL_*` environment variables, existing Cloudflare resource names, saved `data-cmail-*` markers) are unchanged on purpose; new installs get `stanchion-*` names.
- Admin: the Microsoft 365 pages are now one page, **Admin > Microsoft 365** (`/admin/microsoft-365`), with sections for Connection (permission checks and discovered domains), Directory sync, Shared mailbox access (including Include manager accounts), Welcome emails, Mail feed (Graph source, Import older mail, aliases; the legacy journal source is collapsed) and a link card to Standby, which stays its own page. The three old Admin entries (Microsoft 365 sync, Shared mailbox access, Exchange mirror) are gone from the menu; their old addresses (`/admin/m365-sync`, `/admin/m365-mailbox-access`, `/admin/exchange-mirror`) redirect to the matching section. Layout only: every switch, setting and check is the same, with the same manager-only server checks. Docs and the doc `switch:` fields use the new menu path. No migration.

## [0.9.0-beta.2] - 2026-11-17

**Highlights**

- Focused and Other tabs for the Inbox, like Outlook's (off by default).
- A new Graph source for the Exchange mirror, recommended over journal reports (off by default).
- Import older mail from Exchange, with a size, cost and time estimate first.
- Send colleague mail through Exchange, so Outlook users receive it (off by default).
- Multiple mail domains built in, read from the Microsoft 365 tenant with nothing to configure.

### Added
- Exchange mirror, Graph source: **Import older mail** is now a finite, estimated import for managers (Admin > Exchange mirror), replacing the earlier 1 to 90 day box. A slider (1 week, 1 month, 2, 3, 6, 12 months, 2 years, All mail) applies to every mirrored mailbox (people and shared, all domains; Inbox, Sent Items, Archive). **Estimate first (dry run, writes no mail)**: per mailbox and in total the Worker counts the messages (Graph `$count` with `ConsistencyLevel: eventual`) and samples their sizes (Graph's message has no size property, so the `PidTagMessageSize` extended property `Integer 0x0E08` of the newest 50 per folder), in the background within the run's request budget, and shows messages, about size, the D1 size now against the 10 GB per-database limit (Workers Paid; warns from 80%, refuses to start above 100% and refuses All when the size cannot be read), the R2 storage added and its about monthly cost ($0.015 per GB-month, first 10 GB-month free) and the about time (250 messages a run, one run every 5 minutes). A plain warning, then Start needs a tick box and the exact numbers; the Worker counts again first and asks again if the count moved by more than 20%. Stop at once, progress with remaining and time left, one import at a time, audited. Live mail keeps priority: the live pull goes first in every run and, while a count or an import is active, keeps 70% of the run; the import uses its own bounded list pages (resume by second plus `$skip`) and never touches the live delta links; it stops itself at 90% of the D1 limit; a mailbox that keeps failing is left out after six runs and counted. Nothing already in cmail is downloaded or filed twice (Message-ID check); copies are filed as read with no rules or notifications. No migration (three JSON values in `org_settings`, one writer each); the old `graph_mirror_import_older` setting is no longer read. docs/exchange-mirror.md#import-older-mail.
- Exchange mirror **Graph source (recommended)**: reads each mailbox the Microsoft 365 sync linked (people and shared, every organisation domain) from Microsoft 365 with Microsoft Graph, instead of receiving journal reports by email. Journal reports carry the original sender in From, and Cloudflare Email Routing applies that sender's DMARC policy, so reports for mail from any `p=reject` sender were refused before cmail saw them; this source has no SMTP hop. Per mailbox and folder (Inbox, Sent Items, Archive; `M365_GRAPH_MIRROR_ARCHIVE`), a Graph message delta query (`$select` of three fields, `receivedDateTime ge` filter, newest first, 50 per page) with the link stored per mailbox and folder; the Message-ID is looked up first, so replays and messages the journal source (or the normal inbound path) already filed are counted without a download; the rest are read as MIME (`$value`) and filed through the journal path's own filing code (refactored into `prepareMirrorContent` and `fileMirrorCopies`, journal behaviour unchanged), as read, with the time Exchange received them, no rules or notifications, Archive copies to Archive and Sent Items copies to Sent. First pull per folder: the last `M365_GRAPH_MIRROR_LOOKBACK_HOURS` (default 24), at most `M365_GRAPH_MIRROR_INITIAL_CAP` (default 500), the rest counted. 410 restarts from the watermark; 429/503/504 honour Retry-After per mailbox; 403 is counted as outside the scope and Admin shows "permission missing" when every mailbox is refused; each run is bounded (60 s, 400 Graph requests, 5,000 subrequests, 4 pages per folder), round robin with a lease, and resumes where it stopped. Runs on a new `*/5 * * * *` cron (and on `*/10` for older wrangler files). Uses the sync app with `Application Mail.Read` assigned by Exchange RBAC for Applications to a management scope (no Entra `Mail.Read`); exact commands in the docs. Admin > Exchange mirror: switch, Run now, status. Admin > Standby and the docs now say: if Exchange is down, switch as soon as you can, because until then new mail is not received here either. Off by default. Migration `0033_graph_mirror.sql` (additive: two tables). Built and tested with a fake Graph; not yet run against a real tenant. docs/exchange-mirror.md#graph-source-recommended.
- Exchange mirror: new switch **Send colleague mail through Exchange** (Admin > Exchange mirror, off by default, acts only while the mirror is on). Without it, a message from cmail to a colleague on the Exchange-hosted mail domain is filed straight into their cmail mailbox and never reaches Exchange or Outlook (unchanged behaviour). With it on, recipients on the organisation's mail domains (`MAIL_DOMAIN` and, with multi-domain below, the tenant's verified domains) are sent through the outbound provider like external addresses (visible To/Cc unchanged); Exchange delivers them and the mirror files the cmail copy once from the journal report. A mirrored copy that matches the sender's own Sent copy from the last 2 days (same Message-ID as the provider reported it, same subject, the colleague in To or Cc, no DMARC or composite-authentication failure recorded by Exchange) is filed unread with a new-mail notification and counts as a proven colleague for Focused Inbox (needs a provider that reports the Message-ID: the Cloudflare REST route or Postmark). A colleague in Bcc needs a provider that can split the envelope; a later Exchange refusal bounces like any external one. If the switches cannot be read the send fails with the draft kept. Docs: the Exchange settings to check (Reject Direct Send, sender authentication, spoof policies, external tags) and a one-message live proof; the standby switch-over runbook now turns the mirror and this switch off and back on. No migration. docs/exchange-mirror.md#mail-sent-from-stanchion-to-colleagues.
- Welcome emails: recipients, wording, help page and a test button. The sign-in line names the person's userPrincipalName (UPN, what they type at Microsoft sign-in; the sync now records it on the link, migration `0032_m365_sync_upn.sql`, additive), and the email is sent to their own mailbox address (when the UPN is the address, nothing changes). Admin shows **Who would be emailed: N people** and the full list with sign-in names before anything is sent (licensed, enabled people only: the sync already links only enabled members with a usable Exchange plan, so no licence flag was added; shared mailboxes never appear), and **Send a test to me** (the current email to your own address only, subject `[Test] `, not recorded as a welcome send, audited, 5 an hour per manager, works for a manager the sync did not create). Once only and manual Resend are unchanged; the full send still needs the switch. docs/m365-welcome-emails.md.
- Multiple mail domains, built in, with nothing to configure. The organisation's domains are `MAIL_DOMAIN` plus the Microsoft 365 tenant's verified domains, which the Microsoft 365 sync reads with Graph `GET /domains` (`isVerified`, not `isInitial`, `supportedServices` includes `Email`; never `*.onmicrosoft.com`) at most daily and on Sync now, in dry run too (the list is live from its first read; accounts are still created only by a live run), and caches in `org_settings` (`m365_verified_domains`, written only by the email Worker) with the tenant id it was read from; a list from another tenant is replaced by the sync and ignored wherever `M365_TENANT_ID` is set. A failed read (missing `Domain.Read.All`, throttling, an empty or malformed answer, or only the initial domain where real ones were listed) keeps the last good list and shows the problem in Admin > Microsoft 365 sync > Status > Mail domains; a domain is dropped only when two successful reads at least a day apart leave it out, so one odd answer never pauses the people on it; every change is audited (`m365_sync.domains_changed`); turning the sync off freezes the list. One resolver, `orgDomains(env, db)` (`@stanchion/shared/org-domains`), replaces the single-domain checks under the switches that already exist: the Microsoft 365 sync scope (people, shared mailboxes, group and mailbox-type checks), the alias import, Exchange mirror filing (once the tenant's domains have been read successfully, a mailbox on a domain not in the list is counted as unmatched with problem `unmatched_domain`, never filed; with `MAIL_DOMAIN` alone filing is by address as before), local delivery with the mirror and Send colleague mail through Exchange on, Admin > Mailboxes and Admin > People (a domain picker when there is more than one; typed or tampered domains are checked on the server), delegates and the org chart, the public directory, and Focused Inbox's colleague rule (still only with a proven From; the domain list is read in the same statement, no extra query). Phase 1 sending: once the tenant's domains have been read, every send from a mailbox (compose, AI app sends, meeting invitations, replies and cancellations) refuses a From not on `MAIL_DOMAIN` with "Sending from @domain isn't set up yet" (the check is in `sendEmail`; a new meeting is refused before it is saved; system mail from the configured system address is exempt so sign-in codes and notices never stop), so a mailbox on another or a dropped domain can read and file but not send; before discovery nothing changes. The Message-ID follows the From domain when it is an organisation domain. Admin pickers say only `MAIL_DOMAIN` can send for now. Domain checks accept IDN (`xn--`) top-level domains. Standby, Access auto-provisioning and welcome-email From stay on `MAIL_DOMAIN`. With no Microsoft 365 sync (or without `Domain.Read.All`) the list is `MAIL_DOMAIN` alone and behaviour is unchanged (tested). Needs the sync app's new optional application permission `Domain.Read.All` with admin consent. No migration. Built and tested with a fake Graph; not yet run against a real tenant. docs/multi-domain.md.
- Shared mailbox access: **Include manager accounts** (optional, off by default, Admin > Shared mailbox access, org setting `m365_perms_include_managers`). The Microsoft 365 sync never links manager accounts, so Exchange grants to a manager (for example the manager who set up cmail) were always skipped as `trusteeNotLinked`. With the switch on, each round matches an active, unlinked manager to the Entra user whose primary SMTP address (Graph `mail`, via the sync app) equals the manager's cmail address exactly, on `MAIL_DOMAIN`, and is the primary entry (`SMTP:`) in its proxy addresses, only when exactly one enabled member user and one manager match and that user is not already linked (at most 20 managers a round, rotating); the manager then gets the access Exchange grants them (direct and group grants), added or raised only, never lowered or removed, even after the switch is turned off; once the match is gone, those rows are kept and reported (`unlinkedKept`, also for a person whose link is gone). - Focused Inbox: Outlook-style Focused and Other tabs above the Inbox, for any mailbox (personal or shared, whatever the delivery path). Off by default: a manager turns it on in Admin > Settings; each mailbox can then turn it off in Mail > Settings. With the organisation switch off there are no tabs and the Inbox list query is unchanged; the remaining cost is an uncached `org_settings` read per Inbox load and per received-message open, one lookup statement per Inbox delivery, and one extra index write per Inbox insert or move (the new partial index). Move to Other/Focused and "Always move messages from this sender" (per mailbox, never shared), accessible tabs with unread counts, phone layout, and a bounded one-off sort of a mailbox's newest 1,000 Inbox messages. ## [0.9.0-beta.1] - 2026-11-16

First beta. cMail is feature-complete for its main job, primary email for your organisation, and adds optional (off by default) Microsoft 365 add-ons: directory and shared-mailbox sync, Microsoft sign-in for synced staff, welcome emails, the Exchange mirror (journaling), shared-mailbox access sync, the standby test, switch and copy-back, and passkey sign-in. ### Fixed
- Exchange mirror: live journal reports sometimes carry no `X-MS-Exchange-CrossTenant-Id`, and were refused as `wrong_tenant`. The tenant id header is now optional on the outer report: when present it must include this tenant's id (only other ids: refused), and when absent it is not a reason to refuse. With `M365_JOURNAL_REQUIRE_AUTH = "true"`, the SPF path now needs SPF for `M365_JOURNAL_NDR_DOMAIN` (as recorded by Cloudflare) plus `X-MS-Exchange-CrossTenant-AuthAs: Internal` on the outer report, instead of the tenant id. New docs section "What Exchange Online actually stamps", from a live diagnostic. No migration. docs/exchange-mirror.md.
- Exchange mirror, from the first live tenant test: a journal report's From is the original sender and its envelope MAIL FROM is the "undeliverable journal reports" address, so DMARC on the From never proved the tenant and every report was refused with `M365_JOURNAL_REQUIRE_AUTH = "true"`. A report is now authenticated by a DKIM pass from a domain in `M365_JOURNAL_SENDER_DOMAINS` (whatever the From), or by an SPF pass for the new `M365_JOURNAL_NDR_DOMAIN` together with this tenant's id; DMARC on the From is no longer used. The tenant check reads only the outer report's headers and accepts the report when this tenant's id is among its `X-MS-Exchange-CrossTenant-Id` values (a report from another Microsoft 365 organisation's sender carries theirs too, which was refused as `wrong_tenant`). Refused reports now carry a safe header diagnostic in the audit log (an allowlist of tenant, journal and authentication headers of the outer report, each value kept only if GUID, date or token shaped; Authentication-Results reduced to verdicts and domains; DKIM `d=`/`s=` only; a count of such headers in the original). The docs now state that the journal token is the security boundary (the tenant header is attacker-settable; the SPF path relies on unverified Exchange Online MAIL FROM enforcement and needs a dedicated NDR domain; the DKIM path has a replay limit and its `MAIL_DOMAIN` default also matches cmail's own DKIM) and how to rotate the token. No migration. docs/exchange-mirror.md.

- Exchange mirror (optional, off by default): cmail as a live copy ("warm standby") of an Exchange Online tenant with no setup per address. One Exchange journal rule (all messages) sends journal reports to one secret address (`M365_JOURNAL_ADDRESS`, `journal-<token>@<domain>`), one Cloudflare Email Routing rule sends it to the email Worker, and cmail files the attached original (never the report) into every recipient's mailbox by primary address or imported alias, including Bcc and expanded distribution group members, exactly once (same id as the normal inbound path, so repeated and split reports and mail that also arrived directly are filed once), as read, with no notification, no inbox rules and nothing ever sent. Optionally (`M365_JOURNAL_MIRROR_SENT`, off by default until a live test) the sender's copy goes to Sent, only for a cmail user who submitted through Exchange (To/Cc/Bcc envelope lines, the original's From or Sender, and `X-MS-Exchange-CrossTenant-AuthAs: Internal` plus this tenant id on every instance; missing headers mean no Sent copy). A report is trusted only at the exact address, with the manager switch on, no larger than `MAX_INBOUND_BYTES` + 1 MiB (checked before it is read), with `X-MS-Journal-Report`, the tenant id (`M365_TENANT_ID`) where Exchange stamps one (required when `M365_JOURNAL_REQUIRE_AUTH` is "false"), and Cloudflare's own Authentication-Results showing DMARC pass for, or a DKIM signature by, a whole domain in `M365_JOURNAL_SENDER_DOMAINS`; recipient lines are read only after the envelope's single Message-Id, which must equal the original's Message-ID. Anything else is refused at SMTP and audited, never filed. The original gets the normal inbound content limits, sanitizing, blocked attachment types, sender block rules and storage quota, reserved as storage so mirrored copies never use up a mailbox's hourly inbound allowance (skipped copies are counted and audited).
